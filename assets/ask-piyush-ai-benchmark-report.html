Live API Benchmark Report

Piyush Sharma · Cold vs warm-instance benchmark

1. Executive summary

30 of 30 benchmark requests succeeded (100%), with zero HTTP 429 retries at the tested pace of five requests per minute. On a warm instance, median latency was 1.68 seconds, mean latency was 2.29 seconds and p95 latency was 6.22 seconds.

6.22 sWarm p95 latency

The slower tail is concentrated in the experience category (4.60 seconds mean, 4.00 seconds median). The other five categories have medians between 1.45 and 1.78 seconds.

The first warm-up request took 8.61 seconds, while the next two took 6.15 and 7.73 seconds. Since the service idle period was not recorded and subsequent warm-up requests were also slow, the cold-start cost cannot be isolated from this run.

This benchmark measures HTTP success and client-observed latency only. It does not measure answer correctness.

2. Test setup

System under testAsk Piyush AI /chat endpoint: FastAPI in Docker on Google Cloud Run, with Gemini API (free tier) as the LLM.
ClientPython script v2 using urllib; one request at a time.
PacingFive requests per minute, with request start times spaced approximately 12.5 seconds apart.
Timeout90 seconds per request.
Warm-upThree requests using “What is my current role?”, reported separately from the benchmark.
Benchmark suite30 questions: six categories × five questions each — experience, skills, analytics projects, GenAI projects, portfolio and out of scope.
Recorded metricsHTTP status, latency, answer length in words and HTTP 429 retries. Failed requests would be reported separately and excluded from successful-request latency statistics.

Answer length vs latency

The correlation between answer length (words) and latency was 0.35. This is a weak-to-moderate relationship: length explains roughly 12% of the variation in latency (r² ≈ 0.12), so long answers are only a partial explanation for slower requests.

4. Findings

  1. Typical warm latency is about 1.4–2.2 seconds. In four categories — analytics projects, GenAI projects, portfolio and out of scope — every response returned within 2.22 seconds.
  2. The slow tail is concentrated in experience questions. Its 4.60-second mean is more than double any other category. At least two experience requests took about seven seconds or more. Skills has one outlier (5.20 seconds against a 1.69-second median).
  3. The 8.61-second first request is not a clean cold-start number. Requests two and three were also slow at 6.15 and 7.73 seconds. Startup time cannot be isolated from this run.
  4. Role and experience questions are slow. “What is my current role?” took six to eight seconds in the warm-up checks. A plausible but untested explanation is that these questions retrieve more context or trigger longer generation.
  5. The pacing worked at the tested rate. At five requests per minute there were no HTTP 429 errors.
  6. Out-of-scope prompts were as fast as in-scope ones. They returned in 1.41–2.02 seconds, but whether the answers were appropriate refusals has not been checked.

5. Limitations

  • HTTP 2xx success is not the same as a correct answer. No answer quality was scored. The five out-of-scope prompts need manual review for refusal behaviour.
  • This was one run with small samples. With five requests per category, category p95 is effectively the maximum and should be considered indicative only.
  • This was a sequential, single-user test; it does not show behaviour under concurrent load.
  • The idle time before the run, run timestamp and client network path were not recorded. The first-request cold-start estimate is therefore unverified.
  • The LLM runs on the Gemini free tier, so upstream model API variability may contribute to latency.
